# 09. Internationalisation

Status: draft. The English catalog `fixtures/locale-en.json` (122
messages, from v2) is the seed of the normative catalog
`data/messages.en.json`; until that file exists the fixture stands in.

## 1. Catalog

- **I18N-01** Every user-visible string MUST come from the catalog, keyed
  by a stable id (`search.noResults`, `layout.table`, …). Ids are never
  renamed or reused; a message whose meaning changes gets a new id.
- **I18N-02** Messages use ICU MessageFormat: `{name}` arguments,
  `{n, plural, one {…} other {…}}`, `{d, date, long}`. v2 used react-intl
  2 ICU syntax; the same strings parse unchanged.
- **I18N-03** The English catalog is the fallback for every other
  locale, message by message: a missing translation shows English, never
  the id.
- **I18N-04** Translations are managed in Crowdin (project
  `eureka-browser`); the English file is the source and translations are
  pulled as `data/messages.{lang}.json`. Implementations ship English and
  fetch other catalogs on demand from `endpoints.i18n`.
- **I18N-05** Messages that the spec references by id and that
  implementations MUST provide, beyond the v2 set: `item.description`
  (HTML-64, "{filename} displays at {width}x{height}, weighs {size}, and
  was edited on {date}") and `item.descriptionNoDimensions`;
  `listing.caption` ("Contents of {cd}"); `listing.count` ("{n, plural,
  one {# item} other {# items}}" for status announcements);
  `actions.for` ("Actions for {filename}"); `toolbar.listingControls`
  ("Listing controls"); `tree.label` ("Directories");
  `notification.dismiss` ("Dismiss Notification").
- **I18N-06** v2 defaults with concatenation bugs are corrected in the v3
  catalog without changing ids: `rename.item` becomes "Rename Item
  {item}" (space), `file.openInNewTab` interpolates the real filename,
  `pluralChoose` becomes a proper plural message.

## 2. Locale resolution and loading

- **I18N-10** The locale is the first of: the instance `lang` option, the
  document's `lang`, `navigator.languages`, `en`. It is a BCP 47 tag;
  catalog lookup tries the full tag (`pt-BR`), then the language (`pt`),
  then `en`.
- **I18N-11** A non-English catalog is fetched lazily from
  `{endpoints.i18n}{lang}.json`. Until it arrives the instance renders in
  English and MUST NOT block first paint on the fetch. When it arrives,
  text is re-rendered in place; the root's `lang` attribute changes with
  it (HTML-03).
- **I18N-12** The server-rendered Level 0 form is rendered in the locale
  of the request (`?ln=` or `Accept-Language` or the host's choice) and
  the enhanced layer MUST adopt that locale rather than switching to the
  browser's.

## 3. Formatting

- **I18N-20** Dates, times, numbers and plurals are formatted with the
  platform `Intl` APIs in the resolved locale, never with hand-built
  strings. The four date renditions v2 precomputed per item (short date,
  long date with weekday and time zone, and the two search variants) are
  produced by `Intl.DateTimeFormat` in the worker (10 PERF-01) and cached
  per item.
- **I18N-21** File sizes use binary-free decimal units ("95.7 KB",
  "11.44 MB") as v2's `filesize` did, with the unit separated by a
  non-breaking space, and localised digits.
- **I18N-22** Sorting by name uses `Intl.Collator` with `numeric: true`
  and `sensitivity: "base"` so "file2" sorts before "file10" and case
  does not split the list. v2 compared raw code units (uppercase first);
  the conformance test for sorting by name is relaxed on the baseline.
- **I18N-23** The filter matches against the localised display strings
  (what the user sees) as well as the raw filename.

## 4. Direction and layout

- **I18N-30** The stylesheet MUST use logical properties
  (`margin-inline-end`, `inset-inline-start`) so right-to-left locales
  mirror correctly when the root carries `dir="rtl"`. Icons that imply
  direction (expand/collapse carets) flip with the direction.
- **I18N-31** No layout assumes English string lengths: labels wrap, and
  the toolbar reflows (04 LAY-14) rather than truncating.

## 5. Shipped locales

`fixtures/locale-en.json` (en). Translations existing on Crowdin for v2
(nl, and partial others) are imported once the catalog file format is
final; the id set is unchanged so they carry over.
